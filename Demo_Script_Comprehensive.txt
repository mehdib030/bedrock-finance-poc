11. Live Demo #2 — COMPLEX / Controlled-Template Path

Say: Now I will show the controlled-template path. In this POC, CAGR is routed to the COMPLEX path. Bedrock does not generate the SQL. It extracts the parameters, the application validates them, and the application selects the approved revenue_cagr template.

Run: Question: "What was Apple revenue CAGR from 2022 to 2025?"

aws lambda invoke   --function-name sec-bedrock-poc-router   --cli-binary-format raw-in-base64-out   --payload '{"question":"What was Apple revenue CAGR from 2022 to 2025?"}'   output-router-complex.json


cat output-router-complex.json | python -m json.tool

Point out: router_decision.route = COMPLEX; template_id = revenue_cagr; validated_parameters; statement_id; rows.

Say: This path demonstrates a useful governance principle: the model can interpret the user's request, but the application owns the optimized SQL.

Warning: If the CAGR row contains null values because one endpoint is missing in the demo data, do not debug live. Emphasize the routing, validated parameters, template ID, and execution control, or show a previously successful output.
